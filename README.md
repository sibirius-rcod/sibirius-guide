# Сибириус — путеводитель участника

Путеводитель на React, TypeScript и Vite: главная с тремя местами проведения,
17 заведений питания, 9 гостиниц и 3 сувенирных магазина. Есть поиск, фильтры,
выбор филиала, сортировка гостиниц и ссылки на маршруты в Яндекс Картах.
Название форума задаётся в конфигурации сайта.

## Локальный запуск

Название мероприятия и строки баннера задаются объектом `forum`
в `src/config.ts`; полное официальное название `eventName` собирается из него.
Три площадки находятся в блоке «Места проведения» на главной (`#venue`). Старый
`#transport` перенаправляется туда же. Геолокация работает через HTTPS или
localhost; при отказе точку отправления можно выбрать в Яндекс Картах.
Копирование адреса использует Clipboard API с запасным способом.
Адреса и координаты площадок находятся в `src/data/venues.ts`, общий компонент
карточки — `src/components/VenueCard.tsx`. Приложения и ссылки магазинов заданы
в `src/data/transport.ts`, официальные иконки сохранены в `src/assets/apps/`.
Источники и координаты домов перечислены в `src/assets/SOURCES.md`.
Сортировка гостиниц по умолчанию — по расстоянию; второй вариант — по стоимости.

Карточка гостиницы вынесена в `src/components/HotelCard.tsx`. В модели `Hotel`
предусмотрен необязательный массив `photos: { src, alt }[]`: без фотографий
карточка выглядит как раньше, с массивом показывает первое изображение.
Галерея из 3–5 фотографий — следующий этап, изображения пока не добавлены.

Требуется Node.js 22.12+ (можно Node.js 24) и pnpm 11.

```sh
pnpm install --frozen-lockfile
pnpm dev
```

Адрес: **http://127.0.0.1:5173/**. Раздел питания: **http://127.0.0.1:5173/#food**.
Сервер слушает только этот компьютер. Для открытия на другом устройстве
в локальной сети можно явно запустить `pnpm dev --host 0.0.0.0`.

Альтернатива с npm: `npm install`, затем `npm run dev`. Для воспроизводимой
установки предпочтителен pnpm с прилагаемым `pnpm-lock.yaml`.

На текущей машине Node.js доступен во встроенной среде, но не в обычном PATH.
Из PowerShell в папке проекта можно запустить:

```powershell
.\scripts\dev.ps1
```

Скрипт использует имеющийся Node.js. При обычной установке Node можно
пользоваться стандартными командами выше. Если порт 5173 уже занят этим
сайтом, второй сервер запускать не нужно.

## Проверка и сборка

```sh
pnpm test
pnpm build
pnpm preview
```

Дополнительные DOM-проверки навигации и копирования в текущей среде
(с уже установленным `jsdom`): `node scripts/check-ui.mjs`.

Регрессионные проверки прокрутки:

```sh
pnpm test:ui
pnpm exec playwright install chromium
pnpm build
pnpm test:scroll
```

`test:scroll` запускает preview автоматически и проверяет 320, 390, 768,
1440 px для мыши, эмулированного касания и Tab/Enter. Для внешних ссылок,
копирования и элементов управления измеряется `scrollY` до и после первого
и повторного нажатия; внешние назначения перехватываются без выполнения
заказов. Проверяются все три площадки, десять ссылок магазинов, маршруты
питания и сувениров, маршруты и бронирование всех девяти гостиниц, поиск,
выбор адреса, сортировка, меню, якоря и обычная прокрутка. Фокус после Tab
должен оставаться над фиксированным нижним меню.

Существующий сервер или опубликованный сайт проверяется командой
`pnpm test:scroll https://sibirius-rcod.github.io/sibirius-guide/`.
Отчёт сохраняется в `tmp/scroll-check/regression.json`. GitHub Actions запускает
DOM- и браузерные проверки перед публикацией. Исправление в
`src/components/focusVisibility.ts` ограничивает коррекцию видимости переходами
Tab и исключает контейнеры с отрицательным `tabindex`; нажатия указателем
не вызывают программную прокрутку.

Браузерная проверка production-сборки при запущенном `pnpm preview`:
`node scripts/check-browser.mjs`. Требуется установленный Playwright с Chromium
или Chrome. Можно задать пути через `SIBIRIUS_PLAYWRIGHT` и `SIBIRIUS_BROWSER`.
Проверяются ширины 320, 390, 1440 px, копирование, клики маршрутов, якоря,
сортировка и отсутствие горизонтальной прокрутки на всех страницах.
Скриншоты и JSON-отчёт сохраняются в `tmp/visual-check/`.

При запущенном dev-сервере дополнительная проверка загрузки:

```sh
node scripts/check-server.mjs
```

`build` сначала проверяет TypeScript, затем создаёт **dist/**. `preview`
показывает сборку на http://127.0.0.1:4173/. На статический хостинг переносится
содержимое `dist`, а не исходники и PDF. Локальная сборка сама ничего не публикует.

Навигация использует hash (`#home`, `#food`, `#venue`), поэтому серверу
не нужны правила перенаправления SPA. `base: './'` поддерживает размещение
в подпапке. Серверная часть, база данных, внешние API и CDN не используются.
Яндекс Карты открываются обычной внешней ссылкой и требуют интернета.

## GitHub Pages и Netlify

Ветка `main` публикуется через `.github/workflows/pages.yml`: Node.js 24,
pnpm 11.25.0, установка по lock-файлу, проверки, TypeScript и production-сборка,
затем публикация артефакта `dist` в окружение `github-pages`. Источник Pages
в настройках репозитория должен быть **GitHub Actions**. Можно также запустить
workflow вручную во вкладке Actions.

Для Pages workflow задаёт `VITE_BASE_PATH=/sibirius-guide/`. В локальной
разработке и обычной сборке сохраняется относительный `base: './'`.
Маршрутизация использует якоря и работает внутри подпапки без серверных rewrite.
Проверить сборку для Pages локально можно так:

```powershell
$env:VITE_BASE_PATH = '/sibirius-guide/'
pnpm build
pnpm preview
# После остановки preview:
Remove-Item Env:VITE_BASE_PATH
```

Адрес такой локальной сборки: `http://127.0.0.1:4173/sibirius-guide/`.
При подключении репозитория к Netlify настройки берутся из `netlify.toml`:
команда `pnpm build`, папка `dist`, относительный путь ресурсов. Для ручной
загрузки в Netlify выполните обычную сборку без `VITE_BASE_PATH` и загрузите `dist`.

В Git включаются исходный код, локальные ресурсы сайта, конфигурация,
lock-файл, проверки и документация. Зависимости, сборка, временные файлы,
ключи и `.env`, оригиналы PDF, архивы, исследовательские материалы и фотобаза
исключены через `.gitignore`. GitHub CLI хранит авторизацию вне проекта;
пароли и токены в репозиторий не добавляются.

В ограниченной Windows-среде можно установить `SIBIRIUS_SANDBOX=1`:
необязательный адаптер в `vite.config.mjs` позволяет esbuild читать
зависимости через Node без обхода недоступных родительских папок. За пределами
этой среды адаптер выключен. Скрипт `dev.ps1` включает его автоматически.

## Структура

```text
src/
  components/       карточка заведения, модальное окно, брендовая графика
  pages/            главная и раздел питания
  data/             заведения, категории, площадка, формирование маршрутов
  styles/           токены, адаптивная вёрстка, подготовка Arha
  assets/images/    локальные фотографии, оригинальный логотип и паттерны
public/fonts/       место для лицензированных веб-шрифтов
scripts/            проверки и запуск в текущей Windows-среде
```

## Как изменить заведения

Редактируйте **src/data/places.ts**. У каждого объекта есть `id`, `name`,
`type` (`Ресторан`, `Кафе` или `Кофейня`), массив `addresses`, `sourcePage`.
Изображение импортируется из `src/assets/images`, для него задаётся `imageAlt`.

- `hours`: массив строк с расписанием.
- `priceCategory`: ценовая категория, только при подтверждённом источнике.
- `phone`: телефон; ссылка `tel:` формируется автоматически.
- `website`: полный подтверждённый HTTPS-адрес.
- `verifiedAt`: дата реальной проверки. Не заполняйте только потому, что год сменился.

Необязательные поля без данных не отображаются. Если нет фотографии, карточка
покажет нейтральный блок. Несколько адресов автоматически создают выбор
филиала; маршрут строится к выбранному адресу. Все данные остаются локальными.

**Адреса и расписания взяты из «Пут_Уч_3_2025», стр. 4–7, и не проверены на
2026 год.** Это явно указано в интерфейсе. Телефоны и сайты заведений отсутствуют
в этих страницах и не добавлены. Цены не перенесены: актуальная категория не
подтверждена. Фотографии нескольких филиалов — иллюстрации заведения из PDF,
а не отдельные подтверждённые снимки каждого адреса.

## Бренд и шрифты

Палитра: `#542EFF`, `#8B59FF`, `#00D355`, `#FF7C2B`, `#EDF2FF`.
Переменные находятся в **src/styles/global.css**. Оригинальный логотип
и четыре фрагмента фирменной графики извлечены из брендбука 2026 года.
Подробный список источников — **src/assets/SOURCES.md**.

Исходные PDF были предоставлены в корне проекта, а не в папке `references`.
Они сохранены на месте и не попадают в сборку.

Используется системный стек Segoe UI / Arial. Для подключения Arha получите
веб-лицензию и файлы WOFF2, поместите их в `public/fonts`, раскомментируйте
объявления в **src/styles/fonts.css** и добавьте `'Arha'` первым значением
`--font-sans`. Без предоставленной лицензии шрифт из PDF не извлекается.

## Доступность и развитие

Вёрстка предусматривает экраны 360–430 px, планшеты и компьютеры: сетка
категорий 2/4 колонки, карточек питания 1/2 колонки. Есть видимый фокус,
клавиатурная навигация, ссылка пропуска шапки, подписанные поля, native dialog
с Escape и возвратом фокуса, `prefers-reduced-motion`, safe area мобильного меню.
Все фотографии локальные, второстепенные загружаются лениво.

Для следующего этапа PWA можно добавить manifest, service worker и стратегию
кэширования версий HTML/JS/CSS/изображений. Сейчас service worker намеренно
отсутствует, а офлайн-доступ не заявляется. Данные отделены от компонентов,
маршруты статические, загрузка внешних ресурсов для интерфейса не требуется.

## Что проверено

`pnpm test` проверяет данные и источники, поиск по названию и всем адресам,
фильтры, пустую выдачу, формирование маршрутов, наличие фотографий, HTML
обеих страниц и условный вывод телефона, сайта и цены. Синтетические контакты
в тестах не входят в приложение. `pnpm build` проверяет типы и сборку.
Обе проверки пройдены. Дополнительно индекс, 31 модуль dev-сервера и все
локальные изображения успешно загружены по HTTP.

Визуальная проверка браузера в этой сессии недоступна: Computer Use остановился,
поскольку не смог надёжно определить URL окна Chrome. Тесты HTML не заменяют
визуальную проверку размеров, контраста и поведения фокуса в настоящем браузере.
Перед публикацией проверьте 360, 390, 430, 768 и 1440 px, отсутствие горизонтальной
прокрутки, меню (Tab / Shift+Tab / Escape), выбор филиала и внешние маршруты.
